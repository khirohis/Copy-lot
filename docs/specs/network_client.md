# [要件プロンプト] 汎用 Dio インスタンス生成ファクトリーの実装

## 1. 目的 & スコープ

特定の API（翻訳 API 等）に依存しない、**汎用的な HTTP 通信クライアント（`Dio`）を生成するファクトリー基盤**を構築する。
本機能の責務は **「共通の通信設定（タイムアウト値等）が適用された `Dio` インスタンスを生成・提供すること」** に限定する（特定エンドポイントの呼び出しやビジネスロジックは含まない）。

---

## 2. ディレクトリ配置

KISS 原則に基づき、ネットワーク基盤モジュールとして完結させる。

```text
lib/
└── core/
    └── network/
        └── dio_factory.dart # 共通設定が適用された Dio インスタンスを生成するファクトリー
```

---

## 3. 機能要件

### 3.1 Dio インスタンス生成ファクトリー (`DioFactory`)

1. **ファクトリー責務:**
   - 共通の通信設定（タイムアウト値、ヘッダー等）を適用した `Dio` インスタンスを生成。
   - カスタム `BaseOptions` が指定された場合は、その設定を引き継ぎつつ未指定のタイムアウト値にデフォルト値を適用。
2. **基本通信設定（デフォルト値）:**
   - Connect Timeout: 5,000ms
   - Receive Timeout: 5,000ms
   - Send Timeout: 5,000ms

---

## 4. 技術選定 & 実装アプローチ

1. **利用パッケージ:**
   - `dio`: ^5.x
2. **レイヤー構造:**
   - **`DioFactory`:**
     - デフォルトのタイムアウト設定と任意の `BaseOptions` をマージして `Dio` インスタンスを返すファクトリーメソッド（`DioFactory.create({BaseOptions? options})`）を提供。

---

## 5. 検証基準

1. `DioFactory.create()` で生成したインスタンスに、デフォルトのタイムアウト値（5,000ms）が設定されていること。
2. `DioFactory.create(options: ...)` 呼び出し時に、指定した `BaseOptions` の設定が優先され、未指定のタイムアウトにはデフォルト値が適用されること。
3. 静的解析（`flutter analyze`）およびテスト（`flutter test`）でエラーや lint 警告が発生しないこと。
