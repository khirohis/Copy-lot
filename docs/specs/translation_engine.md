# [要件プロンプト] Google Cloud Translation API v2 連携・言語適合ガード・単語/文章境界判定の実装仕様

## 1. 目的 & スコープ

本仕様は、Windows 向け AI 翻訳アプリ「Copy-lot」における **「翻訳エンジン連携」「実行トリガガード（言語適合チェック）」「単語/文章の境界判定ロジック」「API キー検証」** の詳細設計および実装要件を定義する。

無駄な API 呼び出し（課金・クォータ消費）を防ぎ、低レイテンシで適切な翻訳結果を提示するためのドメインロジックおよび外部データソース連携の責務を完結させる。

---

## 2. 機能要件

### 2.1 翻訳方向スイッチ
- **明示的切り替え:**
  - 言語の自動判別（Auto-detect）は行わず、UI 上のトグル/スイッチ（英→日: `en -> ja` / 日→英: `ja -> en`）で明示的に指定された翻訳方向に従う。
  - 翻訳方向が切り替えられた際は、現在表示中の原文テキストを新しい翻訳方向で再翻訳する。

### 2.2 言語適合チェック（実行トリガガード）
無関係な言語や記号のコピーによる不要な API 呼び出しを防ぐため、翻訳実行前に以下の正規表現を用いた言語判定を行う。

1. **日→英モード (`ja -> en`):**
   - **条件:** テキストに日本語文字（ひらがな・カタカナ・漢字）が **1 文字以上** 含まれる場合のみ翻訳を実行。
   - **判定正規表現:** `[\u3040-\u309F\u30A0-\u30FF\u4E00-\u9FFF]`
   - **不一致時:** API 呼び出しを行わず即座にスキップし、UI にスキップ理由を提示。
2. **英→日モード (`en -> ja`):**
   - **条件:** テキストに日本語文字が **含まれない**（英数字・記号・空白等で構成される）場合のみ翻訳を実行。
   - **判定正規表現:** 上記日本語正規表現にマッチしないこと (`!hasMatch`)。
   - **不一致時:** API 呼び出しを行わず即座にスキップし、UI にスキップ理由を提示。
3. **空文字・空白ガード:**
   - トリム後の文字列が空の場合は API 呼び出しを行わずスキップ。

### 2.3 単語 / 文章の境界判定 & 出力フォーマット
翻訳対象テキストが「単語（Word）」か「文章（Sentence）」かを判定し、UI 表示形式およびカードタイトルを切り替える。

1. **英語テキスト (`en -> ja`):**
   - **「単語」判定条件:** 空白区切りの単語数が **2 単語以下**、かつ **文末記号（`.!?`）を含まない**。
     - 出力形式: 主な訳語・訳語候補として提示（カードタイトル: `訳語 (Word)`）。
   - **「文章」判定条件:** 上記以外。
     - 出力形式: 自然な翻訳文として提示（カードタイトル: `翻訳 (Translation)`）。
2. **日本語テキスト (`ja -> en`):**
   - **「単語」判定条件:** 句読点（`。`）および改行を含まず、かつ **文字数が 15 文字以内**。
     - 出力形式: 主な訳語として提示（カードタイトル: `訳語 (Word)`）。
   - **「文章」判定条件:** 上記以外。
     - 出力形式: 自然な翻訳文として提示（カードタイトル: `翻訳 (Translation)`）。

## 3. 外部 API 連携 & データソース仕様

### 3.1 Google Cloud Translation API v2 (Basic) REST
1. **通信方式:**
   - サービスアカウント等の複雑な認証は用いず、ユーザーが入力した API キーをクエリパラメータに付与するシンプルな HTTP POST リクエスト（HTTP/2 対応 Dio を使用）。
2. **エンドポイント & リクエスト:**
   - URL: `https://translation.googleapis.com/language/translate/v2`
   - Query Parameters: `key={API_KEY}`
   - Headers: `Content-Type: application/json`
   - Request Body:
     ```json
     {
       "q": "翻訳対象テキスト",
       "source": "en",
       "target": "ja",
       "format": "text"
     }
     ```
3. **レスポンス処理 & HTML デコード:**
   - レスポンスの `data.translations[0].translatedText` を抽出。
   - API 応答に含まれる HTML エンティティ（`&amp;`, `&lt;`, `&gt;`, `&quot;`, `&#39;`, `&apos;`）を必ずプレーンテキストにアンエスケープして返却する。

### 3.2 エラーハンドリング & オフライン耐性
ネットワーク障害や無効なキー設定時でもアプリをクラッシュさせず、以下のドメイン例外にマッピングして非破壊的通知を行う。

| ステータス / エラー原因 | ドメイン例外 | UI へのフィードバック |
| :--- | :--- | :--- |
| **オフライン / タイムアウト / SocketException** | `NetworkOfflineException` | 「オフラインのため翻訳できません」等の SnackBar 通知 |
| **HTTP 400 / 403 (無効な API キー)** | `InvalidApiKeyException` | 「API キーが無効です。設定を確認してください」通知 |
| **HTTP 429 (クォータ超過 / Rate Limit)** | `QuotaExceededException` | 「API 利用上限を超過しました」通知 |
| **HTTP 5xx / その他のサーバーエラー** | `ApiServerException` | サーバーエラーメッセージの表示 |

### 3.3 API キーの疎通確認（バリデーション）
- 設定画面において、ユーザーが「接続確認」ボタンを押下した際、ダミーテキスト（`"test"`）を用いてテスト翻訳リクエストを実行する。
- 成功時は OK インジケーター、失敗時は例外メッセージに基づく具体的なエラー理由（無効なキー、通信不可等）を表示する。

## 5. 検証基準 & テストケース

1. **言語適合ガードテスト:**
   - `enToJa`: 日本語を含まない英数字・記号で true、日本語を含むテキストで false となること。
   - `jaToEn`: ひらがな・カタカナ・漢字を含むテキストで true、日本語を含まないテキストで false となること。
2. **単語/文章境界判定テスト:**
   - 英語: 2単語以下かつ文末記号なしで `TextType.word`、3単語以上または文末記号（`Hello.` 等）で `TextType.sentence` となること。
   - 日本語: 15文字以内かつ句読点・改行なしで `TextType.word`、16文字以上または `。` / 改行を含む場合は `TextType.sentence` となること。
3. **API クライアント & エラーハンドリングテスト:**
   - 正常レスポンスから HTML エンティティがアンエスケープされて取得できること。
   - 400/403 で `InvalidApiKeyException`、429 で `QuotaExceededException`、接続エラーで `NetworkOfflineException` に正しく変換されること。
